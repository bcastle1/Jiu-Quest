# JiuQuest Unity combat preview

Unity **6000.3.28f1**, URP **17.3.0**, official Unity glTFast **6.20.0**. This is a presentation renderer for the existing JiuQuest app. It does not calculate winners, award points, modify progression, or implement networked fighting.

The source GLBs are the `public/animations/bjj` paired assets. They are authored choreography based on the project's licensed base rig, not captured motion or instructor-reviewed teaching material. Generic `guard_pass` and `armbar` clips do not assert a specific curriculum entry or variant. The newly authored `trap_roll_escape` starts under mount and finishes on top inside guard. Unsupported IDs produce a bridge error rather than substitution.

## Build and tests

Open this directory in the pinned Unity editor, select the Web platform, and run **JiuQuest > Build WebGL preview**. The equivalent batch entry point is `JiuQuest.Combat.Editor.CombatPreviewBuild.BuildWebGL`; launch Unity with `-buildTarget WebGL` so its platform assemblies are referenced before compilation. An optional `-jiuquestOutput` argument changes the output directory; the default is repository `public/unity`. Unity activation and Web Build Support must already be available. The script does not activate a license or accept commercial terms.

`Prepare` stages source GLBs and verifies their SHA-256 copies, creates a reproducible scene and URP configuration, and retains URP Lit. A small custom glTFast material generator preserves semantic cosmetic slot names and uses the same opaque URP shader, avoiding unnecessary glTF shader graphs for these texture-free assets. Generated assets and staged copies are ignored by Git. Builds use gzip with JavaScript decompression fallback, so ordinary static hosting needs no custom content-encoding headers. Unity names the player files by content hash; HTTP choreography requests also include the player's build GUID to avoid stale clip caches.

The builder invokes `tools/unity_release.mjs` after preparation to record `build-source.json`, then verifies the same source/asset fingerprint after compilation. A successful build writes the flat `build-manifest.json`, packed-asset privacy evidence, and `build-sha256.txt` including that source record. It builds in a fresh ignored staging directory and replaces known generated output paths only after verification. The previous local output is retained in ignored Temp. Use the repository PowerShell wrapper to pass the resolved Node executable and validate the completed player. No license, machine paths, or device metadata belong in the release archive.

Run Unity EditMode tests with `-runTests -testPlatform EditMode -testResults <absolute XML path>`. Tests cover strict protocol/move validation, actor identity reversal, cosmetics, reduced-motion parsing, pause/seek/speed, loop behavior, single completion, and camera-envelope fitting across portrait, landscape and oblique views. They do not substitute for a browser render and animation check.

The transitive performance-testing package generates machine and command-line metadata in Resources during its build callback. The project-owned `CombatBuildPrivacy` callback excludes only those generated files from non-test builds after the package callback runs; it does not patch the package. A detailed packed-asset check must confirm exclusion before the public build manifest is written, and `build-privacy-check.json` records the checked asset count without machine data. Actual builds that include test assemblies retain the package's normal test behavior.

## Bridge

Send JSON to `JiuQuestBridge.ReceiveCommand`. Protocol version is 1. Configure with nonempty `instanceId` and `requestId`, optional appearances and camera. The runtime imports the selected paused pair (standing by default) and emits `ready` using the configure request ID only after actual import succeeds. `play` requires an exact supported move ID, accepts `paused` for reduced motion, and applies any supplied cosmetics. Camera values are `front`, `side`, `overhead`, `orbit`. Speed range is 0.1–2; progress range is 0–1. Controls are `pause`, `resume`, `seek`, `setSpeed`, `setCamera`, `setViewport`, `reset`, and `requestState`.

`compactViewport` is accepted on configure/play/setViewport. Compact mode targets 30 fps and disables MSAA while retaining FXAA; larger viewports target 60 fps. Resize updates do not reload choreography. Each imported clip is sampled once across 33 poses to measure visible geometry, then the camera fits that motion envelope for the actual canvas aspect and current angle. The framing also fits intermediate camera angles. Dragging rotates only the selected orbit view; other presets allow the surrounding webpage to scroll. Static dojo geometry is combined by material, and paused playback does not resample bones in Update.

The `.jslib` emits `jiuquest:unity` CustomEvents with protocolVersion, instanceId, requestId, type, moveId, progress, playing, and message. Types are ready/state/completed/error. Ticking events identify the latest accepted command. The runtime rejects another instance's commands, cancels stale asynchronous loads, surfaces glTF load/import failures, and releases imported resources on replacement or teardown. The paired asset contains both actor hierarchies; one paused legacy Animation component is manually sampled from one shared clock. Both actors therefore seek and play in lockstep.

Semantic material slots preserve fighter/opponent customization when `performerSide` changes. `hairStyle` selects one authored hair mesh using the existing app's aliases; bald hides all five variants. `stripes` displays only the supplied count clamped to 0–4, with dark stripes on a white belt and light stripes otherwise. Visibility changes use renderer flags and preserve the animated skeleton. Actor signifiers do not depend on camera orientation. The selected performer always maps to `JQ_Attacker`, the other actor to `JQ_Defender`.
